Scriptorium on Linux: what you need

Everything to run Scriptorium with Docker Compose on a Linux machine, for example a Linux virtual machine in VMware Fusion. Nothing else has to be installed: no .NET, no Node, no Ollama. The cloud model stays off and is never called.

Status: the Docker files have never been built or run yet. The first start is also the first real test: if something fails, copy the last lines of the output and send them to Claude.

1. The machine

WhatMinimumWhy
Processors4 virtual CPUsThe model runs on the processor only (no GPU in a virtual machine), so more CPUs mean faster answers
Memory8 GB of RAM (6 GB free)The 4B model needs about 4 to 5 GB; with less the system can kill it
Disk20 GB freeModel about 3 GB, images 2 to 3 GB, plus the build and your documents
NetworkInternet at the first startTo download the images and the model. After that it can work offline
BrowserAny, inside the same LinuxThe page is only reachable from the machine it runs on (localhost)
Architecturex86-64 or ARM64All the images used exist for both. ARM64 is what Linux gets in VMware Fusion on an Apple Silicon Mac

In VMware Fusion

  • With the virtual machine switched off: Settings → Processors & Memory. Set 4 or more processors and 8192 MB or more of memory.
  • Settings → Hard Disk: at least 20 GB free inside the system (grow the disk if the Linux install left less).

Check from a terminal in Linux

nproc
free -h
df -h /var/lib
uname -m

nproc is the processors, free -h the memory, df the free disk, uname -m the architecture (x86_64 or aarch64).

Only on x86_64: the model is very slow if the virtual machine hides the processor's AVX2 instructions. This must print avx2:

grep -o -m1 avx2 /proc/cpuinfo

If it prints nothing, the hypervisor hides the real processor: change the VM's processor settings (Fusion: Processors & Memory → Advanced options) or use the ARM64 machine.

2. Software to install

SoftwareWhyCheck
Docker EngineRuns the containersdocker --version
Docker Compose v2 (the docker compose plugin)Starts the set of containersdocker compose version
GitTo download the projectgit --version

Docker Desktop is not needed on Linux; Docker Engine is enough. Note the command is docker compose with a space, not the old docker-compose.

Install Docker Engine on Ubuntu

For Debian, write debian instead of ubuntu in the two places where it appears in the docker.asc line and the deb line. Other distributions: follow the official guide at docs.docker.com/engine/install.

sudo apt-get update
sudo apt-get install -y ca-certificates curl git
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Let your user run Docker, and start it

sudo systemctl enable --now docker
sudo usermod -aG docker $USER

Then log out and log in again (or run newgrp docker in that terminal). Without this every Docker command needs sudo and the start command may fail with "permission denied".

docker run --rm hello-world

If it prints "Hello from Docker!", Docker works.

3. Get the project

git clone https://github.com/maurytam/scriptorium.git
cd scriptorium

The Docker files are already on main, so no other branch is needed. They are docker-compose.yml, src/Scriptorium.API/Dockerfile, src/Scriptorium.Web/Dockerfile and src/Scriptorium.Web/nginx.conf. The same steps are in the README, section "With Docker".

4. Start, use, stop

  1. Start (from the project folder): 
    docker compose up --build
    The first time it downloads the base images, builds the API and the web page, and then downloads the model (about 3 GB). This takes many minutes and the terminal shows the progress. A line from the ollama-pull service says Downloading model qwen3.5:4b and later that service ends by itself. Leave the terminal open (or add -d to run in the background and follow the download with docker compose logs -f ollama-pull).
  2. Open http://localhost:8080 in the browser inside Linux. The page with the upload area appears.
  3. Try it with a small fake text file (never a real document): upload it, wait for Ready, press Ask, then ask a question, Summarise and Extract entities. Answers say Answered on this computer. Until the model download ends, questions say the model is not available: that is normal.
  4. Stop (Ctrl+C in the terminal, or from another one): 
    docker compose stop

Everything you may need to type later

CommandWhat it does
docker compose up --buildBuild and start everything. The documents and the model are kept
docker compose up -dStart in the background, without rebuilding
docker compose psWhich parts are running (ollama-pull is expected to be finished)
docker compose logs -f apiFollow the messages of one part (api, web, ollama, ollama-pull)
docker compose exec ollama ollama listShows that the model is downloaded
docker compose stopStop, keep the containers
docker compose downStop and remove the containers. Documents and model are kept
docker compose down -vAlso delete the documents and the model (the next start downloads it again)

5. Settings (optional)

Put them in a file called .env next to docker-compose.yml. Git ignores it, so it is never committed.

WEB_PORT=8080
OLLAMA_MODEL=qwen3.5:4b
ROUTING_CLOUD_ENABLED=false
ANTHROPIC_API_KEY=
  • WEB_PORT: the address of the page, if 8080 is taken.
  • OLLAMA_MODEL: the model to download and use.
  • The cloud is off. It would need ROUTING_CLOUD_ENABLED=true and a key, and it can cost money. Leave both as they are.

6. If something goes wrong

What you seeWhat to do
permission denied ... /var/run/docker.sockYour user is not in the docker group, or you did not log in again after adding it (section 2)
unknown shorthand flag ... docker compose or 'compose' is not a docker commandThe Compose plugin is missing: sudo apt-get install -y docker-compose-plugin
port is already allocated / address already in useSomething uses 8080. See who: sudo ss -ltnp | grep 8080. Or set another WEB_PORT in .env
The build fails while downloading packagesNo internet or a proxy. Try again; the part already built is kept
The model download stops or the machine is offlineRun again docker compose up ollama-pull; it resumes. The rest of the app (upload, list, text) works meanwhile
Questions always say the model is not availableCheck the model: docker compose exec ollama ollama list. If empty, the download did not finish (see above). Look at docker compose logs ollama
The ollama part keeps restarting or the machine freezesNot enough memory. Give the VM more RAM (section 1). Confirm with sudo dmesg | grep -i -E "killed process|out of memory"
The page shows 502 Bad GatewayThe API is not up. docker compose logs api and send the last lines to Claude
Answers take very long, then say the model did not answer in timeA processor-only model is slow; the app waits 120 seconds. Tell Claude: the setting can be exposed in the .env
Disk fulldocker system df shows the space used. docker image prune removes unused images (the data is not touched)

7. Quick checklist

  • ☐ 4+ CPUs, 8 GB RAM, 20 GB disk; on x86 avx2 is printed
  • ☐ docker run --rm hello-world works without sudo
  • ☐ docker compose version answers
  • ☐ the project is cloned (the main branch is enough)
  • ☐ docker compose up --build reaches the model download and then the page opens at http://localhost:8080
  • ☐ a fake file is uploaded, a question is answered with Answered on this computer
  • ☐ after docker compose down and a new start, the file is still listed and the model is not downloaded again
